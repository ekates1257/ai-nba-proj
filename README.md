# NBA Rookie Progression Predictor

Predict an NBA player’s **sophomore-season per-game stats** (Points, Rebounds, Assists) from their **rookie-season per-game stats** using a TensorFlow/Keras neural network.

The repo now has two tracks:
- the original notebook workflow for exploration and coursework
- a new Python/FastAPI service scaffold for a deployable prediction API

## What This Predicts

**Inputs (rookie season features)**
- `GP_r` (games played)
- `MIN_r` (minutes per game)
- `FG_PCT_r` (field goal %)
- `REB_r` (rebounds per game)
- `AST_r` (assists per game)
- `PTS_r` (points per game)
- `TOV_r` (turnovers per game)

**Outputs (sophomore season targets)**
- `PTS_s` (predicted points per game)
- `REB_s` (predicted rebounds per game)
- `AST_s` (predicted assists per game)

## Service-First Repo Structure

- `src/nba_predictor/main.py`
  FastAPI app with the first deployment-oriented endpoints.
- `src/nba_predictor/inference.py`
  Artifact loading and prediction logic.
- `src/nba_predictor/training.py`
  Training pipeline that saves a model, scaler, and metadata for serving.
- `scripts/train_model.py`
  Simple CLI entrypoint for retraining artifacts.
- `artifacts/`
  Deployment-friendly outputs generated by the training script.
- `tests/test_api.py`
  First smoke test for the API surface.

## Legacy Notebook Assets

- `data_processing.ipynb`

- `predictions.ipynb`

## Local Development

Install dependencies:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e .[dev]
```

Train serving artifacts:

```bash
python -m nba_predictor.training
```

Run the API locally:

```bash
uvicorn nba_predictor.main:app --reload
```

Rerun with new changes:
```bash
pip uninstall -y nba-predictor
pip install -e '.[dev]'
uvicorn nba_predictor.main:app --reload
```

Open the docs:

```text
http://127.0.0.1:8000/docs
```

## First API Endpoints

- `GET /health`
  Returns whether the model artifacts are loaded and ready.
- `GET /model-info`
  Returns model version, feature list, targets, and evaluation metadata.
- `POST /predict`
  Accepts rookie-year feature inputs and returns predicted sophomore stats.
- `GET /predict/player/{player_name}`
  Looks up a rookie in `prediction.csv` by name and returns a prediction using their stored rookie-season inputs.

Example request:

```json
{
  "GP_r": 82,
  "MIN_r": 28.4,
  "FG_PCT_r": 0.472,
  "REB_r": 5.8,
  "AST_r": 4.1,
  "PTS_r": 16.7,
  "TOV_r": 2.3
}
```

## Why This Refactor Matters

The original notebook flow refit preprocessing during inference, which is not safe for a production API. The new training path saves:
- the trained model
- the fitted scaler
- model metadata
- confidence interval outputs for the served predictions

This is the foundation needed before containerization, CI/CD, and AWS deployment.
